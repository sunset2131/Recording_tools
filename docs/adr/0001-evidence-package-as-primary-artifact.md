# ADR-0001：以证据包作为录制主产物

- 状态：已接受
- 日期：2026-09-08

## 背景

录制工具需要支持开发人员和 AI 后续生成自动化测试。仅由操作事件直接拼接测试脚本，会把当时的页面结构、异步网络结果、SPA 路由和前端错误丢失，且容易生成脆弱定位器。

## 决策

录制阶段以结构化证据包为主产物，不自动生成最终测试脚本。证据包包含逻辑步骤、原始事件、页面前后状态、定位候选、网络元数据、控制台事件和可选 Trace；同时继续导出旧格式动作 JSON 以保持兼容。

## 备选方案

1. 直接生成 Playwright 脚本：交付直观，但缺少业务预期，定位和断言容易错误，事后难以诊断。
2. 只保存 Playwright Trace/HAR：实现较快，但格式偏工具内部，后续 AI 和旧消费者需要额外解析，且步骤语义不明确。
3. 以证据包为主产物：文件较多、实现成本较高，但可离线复盘、可审计，并能支持多种后续脚本生成器。

## 后果

- 需要维护版本化的 `evidence.json` 数据契约和完整性校验。
- 录制目录占用空间高于单个动作 JSON，因此引入响应体上限、DOM 上限和 ZIP 分发策略。
- 证据会保留原始表单值、DOM 文本和允许保存的响应体，可能含有敏感数据；本次不自动脱敏、上传或删除。Cookie、认证头、storage state 和其他可复用登录凭据必须排除，目录的访问、传输和保留由使用方负责。
- 业务断言不再由录制器猜测；后续通过检查点或单独的测试设计阶段补充。
- 证据包成为新的稳定接口，脚本生成器可以独立演进而不改变录制核心。
